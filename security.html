Security

Current controls, locked features and release prerequisites.

Security position: public legal-information functions are enabled first; sensitive-data functions remain locked until their controls exist.

1. Current controls

  • Public legal-information data only in the current D1 corpus.
  • Source-first records with provenance and Human Gate review fields.
  • Private Zenodo editor/upload URLs are not exposed by the public portal or API.
  • Security response headers are added when assets are served through the Cloudflare Worker.
  • Cross-origin API access is limited to the AI Advokat production origins and local development.

2. Features intentionally disabled

  • Confidential document upload.
  • Client case workspace.
  • Role-based case access.
  • Unreviewed generative legal conclusions.

3. Requirements before secure workspace release

Authentication, role-based authorization, encrypted storage, retention and deletion rules, audit logging, incident handling, backup/recovery and tested access separation must be in place before sensitive client data is accepted.

4. Responsible disclosure

Report a suspected security issue privately to aiadvokat16@gmail.com. Do not include client secrets in the initial report.

5. No certification claim

This page describes implemented and planned controls. It does not claim a security certification, regulatory certification or independent audit that has not actually occurred.
