Reference types (not generated SDK):
```ts
type RevisionRef = {caseId:string; draftId:string; revisionId:string; revision:number;
  contentSha:string; sourceSnapshotSha:string; authoritySnapshotSha:string;
  sourceEpoch:number; authorityEpoch:number; authorizationEpoch:number; gateEpoch:number};
type ParentCAS = {expectedParentRevisionId:string; expectedParentRevision:number;
  expectedParentContentSha:string; idempotencyKey:string};
type AppendRequest = ParentCAS & {content:string}; // UTF-8 working text, server hashes
type RollbackRequest = ParentCAS & {targetRevisionId:string}; // new revision, never delete
type ReviewRequest = {contractVersion:"oic2.v2"; revision:RevisionRef;
  decision:"approved"|"rejected"|"needs_revision"|"revoked"; reason:string};
type ExportRequest = {contractVersion:"oic2.v2"; revision:RevisionRef;
  mode:"working"|"professional"; format:"docx"|"pdf"};
```
Proposed success JSON: {ok:true,revision:RevisionRef} for append/rollback (201); review adds decisionId,decidedAt,server actor ref,professionalUseLocked; export artifact binary after authorized release and audit receipt. Review request ref is expectation, not authority. Server computes identity/hash/snapshots, derives actor and permission, checks exact head, active hold and epochs atomically. Monotonic epochs avoid stale approval revival; idempotency bound to actor/case/draft/operation/payload. Approval references immutable revision and canonical export AST; approval alone never overrides LEGAL_HOLD. Rollback creates new identity even when text SHA equals historical SHA. Durable CAS requires local D1 transaction validation, no in-memory mutex as evidence. R2 bytes staged privately with digest and atomic authoritative pointer; revalidate before export release. Professional export never accepts client report/content/actor or forged approval; server renders reviewed immutable AST and records content/model/artifact hashes and renderer version. No autonomous filing, signature or transmission.

Proposed errors: 400 invalid payload; 401 no membership; 403 role/hold denied; 404 inaccessible; 409 CAS/snapshot/approval mismatch, idempotency conflict; 413 limit; 415 media; 429 quota; 503 provider/storage/contract unavailable. Exact final codes/statuses require Worker tests. UI preserves machine codes and redacts sensitive details. No secrets or actual client facts in fixtures.

### Local atomic document and revision candidate

The existing request formats and actor authorization are used. With the isolated atomic schema enabled, the Worker binds extraction, analysis provenance, saved revision and review receipt to a server-derived `sourceEpoch`. An extraction or pre-review source conflict returns HTTP 409, including when the latest object reuses a previous digest. The review's audit insert also rejects a concurrent revision or decision change or lost write access. This mode takes revision history from D1 and rejects a first atomic write over legacy history. An approved receipt remains historical with `releaseAuthorized:false`; `sourceEpoch` is evidence about documents and does not certify current law or professional delivery.

Publication and review writes in this mode compare the authorization captured when the request began with the current account, workspace and actor-specific grant epochs. A lost and restored permission yields a conflict for the original request. Historical receipts expose an `authorizationStale` boolean when the captured epoch or access deadline no longer matches. Receipts recorded before this evidence was introduced appear as stale in this mode. The exact access deadline and internal counters stay in D1.

The atomic mode compares the shared D1 corpus and private case-classification epochs, compiled Worker policy digest, and legal date window captured during analysis. The window ends at the next civil midnight in Europe/Skopje. An explicit ISO reference date controls the queried version, while the review still expires at the current civil-day boundary. Revision publication and non-revocation reviews compare these fields in the same conditional D1 write as the existing guards. A stale snapshot returns HTTP 409 and requires fresh analysis. A new analysis returns HTTP 503 while the compiled digest is unregistered or differs from the D1 policy row. Historical reviews expose `authorityStale` when the policy or time window is stale. Historical revocation remains available.

The isolated post-render export validation has an internal D1 receipt and exposes no HTTP endpoint. The receipt carries model and artifact SHA-256 and `releaseAuthorized:false`. The existing HTTP route returns 409 for professional mode while HOLD is active, including a request without a client report. Working downloads and browser rendering models remain available.
